A download manager that does the hard part itself.

RDM splits a file into up to 32 parallel ranges, re-splits slow segments while the transfer runs, and resumes from the last byte after a crash. It also detects video the way IDM does — by watching what the player actually fetches — and assembles HLS, DASH and yt-dlp-supported streams.

What makes it different

Segmented, then re-segmented

Up to 32 byte-range requests in parallel, written at their own offsets. A lagging segment is split again mid-flight so one slow connection can't stall the file.

Resume that survives a crash

The segment table is checkpointed to a sidecar, so killing the process — or losing power — continues from the last byte instead of starting over.

Speed limits, both kinds

A global cap, plus a per-download limit in the detail panel. Named queues carry their own limits and concurrency.

Video, the IDM way

The extension watches the network and the page's own fetch/XHR/MSE calls, so manifests and media behind blob: players are found — then RDM routes on the real media type.

Streams assembled properly

HLS playlists are assembled and remuxed to .mp4 with ffmpeg; DASH manifests and the long tail of sites go to yt-dlp, with a quality picker from its format list.

Site grabber

Crawl a page to a chosen depth, stay on-origin or include CDNs, filter with globs like *.mp4, tick what you want, and queue it all in one click.

Native everywhere

One Rust binary with a Dioxus UI: tray menu with live downloads, dark/light/system themes, clipboard capture, a daily scheduler.

Eight languages, RTL done right

English, Spanish, French, German, Portuguese, Russian, Chinese and Persian — with logical layout properties so the RTL UI doesn't overflow. The bundled Vazirmatn font covers Latin and Arabic script in one face.

How video detection works

RDM never guesses from a URL alone. The extension reports what the player actually requested, with the metadata needed to download it later.

SignalWhat it catches
Network monitor (webRequest) Manifests and media classified by response Content-Type — including signed, expiring and extension-less stream URLs
URL monitor Direct .mp4/.webm/… and .m3u8/.mpd
DOM scan <video>/<audio>/<source>, including nodes added after load
Page-context hooks fetch, XMLHttpRequest and the MediaSource API — the traffic behind blob: players that extensions cannot see from their own world

Candidates are handed to RDM with their media type and referer, and the engine routes on that: .m3u8 is assembled (then remuxed to .mp4), a DASH manifest goes to yt-dlp, a plain video downloads directly. Anything RDM can't see through falls back to the page URL and yt-dlp's extractors. DRM-protected streams are deliberately out of scope.

Install

Pick a channel, or take a build straight from the latest release. 

curl -fsSL https://mehrabix.github.io/rdm/rdm.gpg \
  | sudo tee /usr/share/keyrings/rdm.gpg >/dev/null
echo "deb [signed-by=/usr/share/keyrings/rdm.gpg] https://mehrabix.github.io/rdm/apt stable main" \
  | sudo tee /etc/apt/sources.list.d/rdm.list
sudo apt update && sudo apt install rdm

If apt complains the key has an unsupported filetype, pipe it through gpg --dearmor. 

sudo curl -fsSL https://mehrabix.github.io/rdm/rdm.asc \
  -o /etc/pki/rpm-gpg/RPM-GPG-KEY-rdm
sudo dnf config-manager --add-repo https://mehrabix.github.io/rdm/rpm
sudo dnf install rdm
brew tap mehrabix/rdm
brew install --cask rdm

Installs RDM.app (Apple silicon).

scoop bucket add mehrabix https://github.com/mehrabix/scoop-bucket
scoop install rdm
sudo snap install rust-download-manager --edge

Published to edge while it stabilises; the command is rust-download-manager.

  • Linux — AppImage, .deb, .rpm
  • macOS — .dmg or zipped RDM.app
  • Windows — .msi
  • Extension — .crx, Chromium .zip, Firefox .xpi

Every artifact ships a .sha256 checksum.

Browser integration

A right-click Download using RDM entry, a toolbar popup listing everything detected on the page, and a dismissible badge over every video that opens a quality menu.

  1. Install RDM — the .deb also registers the native-messaging host.
  2. From a tarball, run scripts/install-browser-host.sh once.
  3. Load the extension: Load unpacked from chrome://extensions, or drag the released .crx; Firefox uses the .xpi from about:debugging.
  4. Start RDM — the extension talks to it over a local Unix socket.

Cookies are read only for the site you're downloading from, and the socket accepts http(s) URLs only — it can never be asked to run a command.
